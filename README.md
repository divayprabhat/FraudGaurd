# FRAUDGUARD

Fraud detection and monitoring web app built around `notebook.ipynb` (Fraud Detection Model and Monitoring).
React + TypeScript + Tailwind + Recharts frontend, FastAPI + scikit-learn backend.

## What comes from the notebook

| Area | Source |
|---|---|
| 8 model inputs | `amount, transaction_hour, merchant_category, foreign_transaction, location_mismatch, device_trust_score, velocity_last_24h, cardholder_age` |
| Models | Logistic Regression vs Random Forest, selected by validation PR-AUC (Random Forest) |
| Decision threshold | Maximum validation F1 (0.32 in the notebook run), read from the model artifact |
| Risk bands | LOW below threshold, MEDIUM from threshold, HIGH from `max(threshold, 0.70)` |
| Alert rules | Predicted fraud rate > 5% (min 100 events), p95 latency > 250 ms, freshness SLA < 99% within 30 s |
| Live Monitoring | Replay of the held-out test split (max 5,000 events), as in the notebook. **Simulated.** |

## Quick start

```bash
./start.sh          # macOS / Linux
start.bat           # Windows
```
Then open **http://localhost:8000**. The launcher creates `backend/.venv`, installs `requirements.txt`, builds the UI if
`frontend/dist` is missing (needs Node 18+), and serves API + UI from one process.

Manual run (two terminals, hot reload):
```bash
cd backend && python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt && uvicorn app.main:app --reload --port 8000
cd frontend && npm install && npm run dev                          # http://localhost:5173 (proxies /api to :8000)
```

## Using your own dataset (important)

The notebook's saved results (Random Forest, threshold 0.32, 10,000 rows, 151 frauds, 5 merchant categories) came from a real
`credit_card_fraud_10k.csv` that was **not** included in the upload. The `backend/data/credit_card_fraud_10k.csv` shipped here is
a 20,000-row **synthetic** stand-in (7 categories, generated by the notebook's fallback generator), so the app currently
shows a weaker Logistic Regression model and flags itself as "Synthetic data" in Settings.

To get your notebook's real numbers: **replace `backend/data/credit_card_fraud_10k.csv` with your file and restart the API.**
The API compares the CSV's hash with the one the model was trained on and retrains automatically (a few seconds) using the
notebook's exact pipeline: same splits, seeds, models and threshold rule. No script needed. It also retrains by itself if the
model file is missing, corrupt, or was built with a different scikit-learn version.
Required columns: `transaction_id, amount, transaction_hour, merchant_category, foreign_transaction, location_mismatch,
device_trust_score, velocity_last_24h, cardholder_age, is_fraud`.

Manual training: `cd backend && python scripts/train_model.py [--csv path]`.

Environment variables: `FRAUDGUARD_DATA_CSV` (dataset path), `FRAUDGUARD_ARTIFACT_DIR`, `FRAUDGUARD_AUTO_TRAIN=0` (disable
auto-training), `FRAUDGUARD_CORS_ORIGINS` (comma-separated, default the Vite dev server).

## Tests

```bash
cd backend && pip install -r requirements-dev.txt && pytest
```
Covers input validation, scoring and risk bands, transactions paging/search/sort, dashboard/performance consistency, replay
start/stop/reset, alert status updates, retraining on a changed CSV, recovery from a corrupt model, and API/SPA routing.

## API

`GET /api/health` · `GET /api/meta` · `POST /api/predict` (422 for out-of-range values or a merchant category the model was not trained on) · `GET /api/transactions` (search, risk, sort, order, page) ·
`GET /api/transactions/{id}` · `GET /api/dashboard` · `GET /api/performance` · `GET /api/monitoring` ·
`POST /api/monitoring/{start|stop|reset}` · `GET /api/alerts` · `PATCH /api/alerts/{id}`. Docs at `/docs`.

## Things worth knowing

- **Timestamps:** the dataset has none. The Timestamp column is when this server scored the transaction.
  The hourly chart uses the real `transaction_hour` feature.
- **Overview KPIs:** detection rate (recall) and accuracy are the notebook's test-set metrics; latency is measured on your machine.
- **Latency:** measured around each real model call (single-row, `n_jobs=1` at inference). The notebook's replay measured ~0 ms
  because it timed a no-op; the numbers here are real scoring time, so expect tens of ms for a 250-tree forest.
- **Throughput:** the replay is paced (8 events/s); "capacity" shows how fast the model could score.
- **Persistence:** analysed transactions, replay state and alert statuses are in memory and reset on API restart.
- **Currency:** amounts have no currency in the dataset, so none is shown.
- **Alerts:** raised from monitoring thresholds above, plus one per HIGH-risk transaction (replay or manual).
  Threshold alerts auto-resolve when the condition clears.
